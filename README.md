# 🛡 Telegram Guard

Бот, который сохраняет удалённые и изменённые сообщения из ваших личных чатов и
присылает их вам вместе с вложениями. Плюс команды с префиксом `.`, которые вы
пишете прямо в переписке — в том числе `.mute`, мгновенно удаляющий сообщения
собеседника у всех.

```
Вы:  .mute
     🔇 ▱▱▱▱▱▱
     🔇 ▰▰▰▰▱▱
     🔇 Вы были замучены ▌
     🔇 Вы были замучены на неопределённый срок.
     🔇 Вы были замучены на неопределённый срок.   ← жирным, финальный кадр
```

## Как это работает

Обычный бот не видит удалений: Bot API таких событий не отдаёт. Но у Telegram
есть **Telegram Business** — в настройках можно подключить бота к своим личным
чатам, и тогда он начинает получать `deleted_business_messages`, то есть
удаления приходят официально.

Поэтому основной режим — **Business**: нужен только токен из
[@BotFather](https://t.me/BotFather), никаких API-ключей и строк сессии.
Требуется Telegram Premium — без подписки раздела Business в настройках нет.

Второй режим — **юзербот** на MTProto (Telethon) от вашего аккаунта. Он нужен,
только если Premium нет или важны групповые чаты: Business работает лишь с
личными. Это серая зона правил Telegram, так что включайте осознанно.

Режимы независимы и складываются: можно включить оба, тогда бот отвечает за
личные чаты и доставку отчётов, а юзербот — за группы.

| | Business | Юзербот |
|---|---|---|
| Что нужно | `BOT_TOKEN` + Premium | `API_ID`, `API_HASH`, `SESSION` |
| Личные чаты | да | да |
| Группы и каналы | нет | да |
| Правила Telegram | штатный API | серая зона |

## Подключение

1. [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен.
2. Положить токен в `BOT_TOKEN` и запустить (см. ниже).
3. Открыть чат со своим ботом → **Start**. Бот пришлёт инструкцию.
4. Настройки Telegram → **Telegram для бизнеса** → **Чат-боты** → вставить
   юзернейм бота → выбрать чаты → выдать разрешения: читать сообщения,
   отвечать, **удалять сообщения — и свои, и собеседника**.
5. Бот подтвердит подключение и покажет, какие права реально выданы.

Команда `/connect` повторяет инструкцию в любой момент, `/status` показывает
текущие права и что без них не работает.

## Что умеет

**Антиудаление.** Входящие сообщения кладутся в локальный кэш (SQLite) вместе с
`file_id` вложений. Когда сообщение удаляют, вам приходит карточка: кто, где,
когда, текст и само вложение — фото, голосовое, кружок, файл. Правки приходят
как «было → стало».

**`.mute`.** Пишете `.mute` в личке — команда исчезает из переписки, а на её
месте появляется уведомление с анимацией набора: «Вы были замучены на
неопределённый срок». Дальше все сообщения собеседника удаляются у всех сразу
после отправки, но не пропадают для вас: перехваченное приходит вам в личку с
ботом. Снимается `.unmute`.

### Команды в переписке (режим Business)

Пишете вы, от своего имени. 💬 — результат виден собеседнику, 🔒 — ответ
приходит только вам в чат с ботом.

| | Команда | Что делает |
|---|---|---|
| 💬 | `.mute [срок] [причина]` | удалять все новые сообщения собеседника |
| 💬 | `.unmute` | снять мут |
| 💬 | `.gmute` / `.ungmute` | то же самое во всех личных чатах |
| 🔒 | `.mutelist` | список активных мутов |
| 🔒 | `.del` (реплаем) | удалить сообщение у всех |
| 🔒 | `.purge` (реплаем) | удалить всё от реплая до текущего |
| 🔒 | `.deleted [N]` | последние удалённые в этом чате |
| 🔒 | `.antidelete on/off`, `.ignore` | настройки для этого чата |
| 🔒 | `.id`, `.ping`, `.stats`, `.help` | диагностика |

Сроки: `10m`, `2h`, `1d`, `1w` (без единицы — минуты). Флаг `-q` отключает
анимацию.

### Команды в чате с ботом

`/status` · `/deleted [N]` · `/mutes` · `/unmute <id>` · `/backup` ·
`/connect` · `/help`

### Дополнительно в режиме юзербота

Те же команды плюс группы: `.ban` `.kick` `.tmute` `.promote` `.pin`,
`.purgeme`, `.sd`, `.afk`, заметки `.save`/`.get`/`.notes`, `.restore`,
`.export`, `.restart`, `.update`. Полный список — `.help`.

## Запуск

```bash
git clone <репозиторий> && cd new2
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # достаточно заполнить BOT_TOKEN
python main.py
```

Через Docker:

```bash
docker compose up -d --build
docker compose logs -f
```

Режим юзербота (необязательно): взять `API_ID` / `API_HASH` на
`my.telegram.org`, затем `python scripts/gen_session.py` и вписать `SESSION`.
Строка сессии = полный доступ к аккаунту, в git ей не место.

## Хостинг

Рекомендуемый бесплатный вариант — **Koyeb**: деплой прямо из GitHub, инстанс
не засыпает. Пошагово и с альтернативами — в [DEPLOY.md](DEPLOY.md).

Диск на бесплатных тарифах эфемерный, поэтому база регулярно уезжает копией в
Telegram (`BACKUP_EVERY_MIN`). Чтобы поднять её после передеплоя, достаточно
переслать этот файл боту — он проверит его и подставит вместо текущей базы.
На хостах с постоянным томом (Fly.io) это не нужно.

## Настройки

Все параметры с комментариями — в [`.env.example`](.env.example).

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BOT_TOKEN` | — | токен из @BotFather (режим Business) |
| `OWNER_ID` | `0` | кому слать отчёты; `0` = определится сам |
| `SESSION` | — | строка сессии (режим юзербота) |
| `PREFIX` | `.` | префикс команд в переписке |
| `MUTE_ANIM` | `type` | `type` / `bar` / `off` — стиль анимации |
| `ANTIDELETE_GROUPS` | `0` | антиудаление в группах (только юзербот) |
| `CACHE_TTL_HOURS` | `48` | сколько держать кэш сообщений |
| `BACKUP_EVERY_MIN` | `60` | период бэкапа базы |

Антиудаление по умолчанию работает **только в личках**. В группах его нужно
включать точечно (`.antidelete on`) — чтобы не собирать переписку посторонних.

## Разработка

```bash
pip install -r requirements-dev.txt
pytest -q        # 166 тестов
ruff check .
```

Структура:

```
bot/        Bot API: клиент, long polling, режим Business, команды «.» и «/»
core/       общий движок: анимация, диспетчер юзербота, отчёты, бэкапы
modules/    команды и обработчики юзербота, по файлу на раздел
db.py       SQLite: кэш, журнал удалений, муты, настройки, подключения
main.py     запуск обоих режимов
```

Новая команда в переписке — функция с `@bizcmd(...)` в `bot/dotcmd.py`,
новая команда юзербота — `@command(...)` в любом модуле `modules/`.
