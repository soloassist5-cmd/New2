# 🛡 Telegram Guard

Юзербот на [Telethon](https://docs.telethon.dev/): сохраняет удалённые и изменённые
сообщения, умеет мгновенно удалять сообщения собеседника (`.mute`) и понимает
команды с префиксом `.`, которые вы пишете от своего имени в любом чате.

```
Вы:  .mute
     🔇 ▱▱▱▱▱▱
     🔇 ▰▰▰▰▱▱
     🔇 Вы были замучены ▌
     🔇 Вы были замучены на неопределённый срок.
     🔇 Вы были замучены на неопределённый срок.   ← жирным, финальный кадр
```

## Почему юзербот, а не обычный бот

Bot API **не присылает события об удалении сообщений** — обычный бот, добавленный
в чат, физически не может узнать, что сообщение удалили, и не видит переписку в
личке. Поэтому ядро работает по MTProto от вашего аккаунта. Команды реагируют
только на **исходящие** сообщения, так что чужой человек их не вызовет.

> Автоматизация аккаунта формально в серой зоне правил Telegram. Для личного
> использования без рассылок рисков практически нет, но ценный аккаунт лучше не
> использовать: заведите отдельный.

## Что умеет

**Антиудаление.** Каждое входящее сообщение кладётся в локальный кэш (SQLite),
медиа при этом копируется в приватный лог-чат — после удаления файл уже не
скачать, поэтому снимок делается сразу. Когда приходит событие удаления, в
лог-чат уходит карточка: кто, где, когда, текст и вложение. Правки логируются
как «было → стало».

**`.mute`.** Пишете `.mute` в личке — ваше же сообщение с анимацией превращается
в «🔇 Вы были замучены на неопределённый срок», а все последующие сообщения
собеседника удаляются у всех сразу после отправки. При этом они не пропадают:
перехваченное падает в лог-чат, так что вы их читаете, а собеседник видит, что
его сообщения исчезают. Снимается `.unmute`.

Полный список — `.help`, подробности по команде — `.help mute`.

| Раздел | Команды |
|---|---|
| Мут | `.mute` `.unmute` `.gmute` `.ungmute` `.mutelist` |
| Антиудаление | `.antidelete` `.logedits` `.savemedia` `.ignore` `.deleted` `.restore` `.export` |
| Чистка | `.del` `.purge` `.purgeme` `.sd` |
| Админ (группы) | `.ban` `.unban` `.kick` `.tmute` `.untmute` `.promote` `.demote` `.pin` `.unpin` |
| AFK | `.afk` `.unafk` |
| Заметки | `.save` `.get` `.notes` `.delnote` |
| Инфо | `.ping` `.id` `.info` `.stats` `.json` |
| Система | `.help` `.alive` `.backup` `.cleanup` `.logs` `.restart` `.update` |

Примеры:

```
.mute                  # собеседника в этой личке, бессрочно
.mute 2h капслок       # на два часа, с причиной
.mute @user 30m        # конкретного человека
.gmute -q              # глобально, без анимации
.deleted 20            # последние 20 удалённых в этом чате
.restore               # вернуть последнее удалённое обратно в чат
.purge                 # реплаем: снести всё от того сообщения до текущего
```

## Запуск локально

```bash
git clone <репозиторий> && cd new2
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env          # заполнить API_ID / API_HASH с my.telegram.org
python scripts/gen_session.py # получить SESSION, вписать в .env
python main.py
```

Создайте приватный канал для логов, добавьте туда себя и укажите его id в
`LOG_CHAT` (можно оставить `me` — тогда логи пойдут в «Избранное»).

Через Docker:

```bash
docker compose up -d --build
docker compose logs -f
```

## Хостинг

Рекомендуемый бесплатный вариант — **Koyeb** (деплой прямо из GitHub, инстанс не
засыпает). Подробный разбор вариантов и пошаговая настройка — в
[DEPLOY.md](DEPLOY.md).

База на бесплатных хостах живёт на эфемерном диске, поэтому она периодически
выгружается в лог-чат (`BACKUP_EVERY_MIN`) и подтягивается оттуда при старте
(`RESTORE_ON_START`). Пересоздание контейнера историю не теряет.

## Настройки

Все параметры — в [`.env.example`](.env.example) с комментариями. Наиболее
полезные:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PREFIX` | `.` | префикс команд |
| `LOG_CHAT` | `me` | куда писать логи |
| `MUTE_ANIM` | `type` | `type` / `bar` / `off` — стиль анимации |
| `ANIM_DELAY` | `0.4` | пауза между кадрами, сек |
| `ANTIDELETE_GROUPS` | `0` | включать антиудаление и в группах |
| `CACHE_TTL_HOURS` | `48` | сколько держать кэш сообщений |
| `BACKUP_EVERY_MIN` | `60` | период бэкапа базы в лог-чат |

По умолчанию антиудаление работает **только в личках**. В группах его нужно
включать точечно (`.antidelete on` в нужном чате) или глобально через
`ANTIDELETE_GROUPS=1` — по умолчанию оно выключено, чтобы не собирать переписку
посторонних людей.

## Разработка

```bash
pip install -r requirements-dev.txt
pytest -q        # 78 тестов: анимация, БД, диспетчер, сквозной сценарий мута
ruff check .
```

Структура: `core/` — движок (диспетчер команд, анимация, хранилище медиа,
бэкапы), `modules/` — команды и обработчики событий, по файлу на раздел.
Новая команда — это функция с декоратором `@command(...)` в любом модуле.
