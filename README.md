# 🛡 Telegram Guard

Бот, который сохраняет удалённые и изменённые сообщения из ваших личных чатов и
присылает их вам вместе с вложениями. Плюс команды с префиксом `.`, которые вы
пишете прямо в переписке — в том числе `.mute`, мгновенно удаляющий сообщения
собеседника у всех.

```
Вы:  .mute
     🔇 ▱▱▱▱▱▱
     🔇 ▰▰▰▰▱▱
     🔇 Вы были замучены ▌
     🔇 Вы были замучены на неопределённый срок.
     🔇 Вы были замучены на неопределённый срок.   ← жирным, финальный кадр
```

## Как это работает

Обычный бот не видит удалений: Bot API таких событий не отдаёт. Но у Telegram
есть **Telegram Business** — в настройках можно подключить бота к своим личным
чатам, и тогда он начинает получать `deleted_business_messages`, то есть
удаления приходят официально.

Поэтому основной режим — **Business**: нужен только токен из
[@BotFather](https://t.me/BotFather), никаких API-ключей и строк сессии.
Требуется Telegram Premium — без подписки раздела Business в настройках нет.

Второй режим — **юзербот** на MTProto (Telethon) от вашего аккаунта. Он нужен,
только если Premium нет или важны групповые чаты: Business работает лишь с
личными. Это серая зона правил Telegram, так что включайте осознанно.

Режимы независимы и складываются: можно включить оба, тогда бот отвечает за
личные чаты и доставку отчётов, а юзербот — за группы.

| | Business | Юзербот |
|---|---|---|
| Что нужно | `BOT_TOKEN` + Premium | `API_ID`, `API_HASH`, `SESSION` |
| Личные чаты | да | да |
| Группы и каналы | нет | да |
| Правила Telegram | штатный API | серая зона |

## Кто может пользоваться

Ботом может пользоваться несколько человек, и у каждого **свои** данные:
удалённые сообщения, муты, белый список и режим «не беспокоить» не пересекаются.
Это не косметика — id личного чата в Bot API совпадает с id собеседника и
одинаков для всех, так что без разделения по владельцу люди видели бы переписку
друг друга.

Доступ выдаёт **администратор** — тот, чей id указан в `OWNER_ID`. Когда
незнакомый человек пишет боту `/start` или подключает его в своих настройках
Business, администратору приходит карточка с именем и id и двумя кнопками:

```
🔐 Запрос доступа к боту
👤 Иван Петров
🆔 123456789
🔗 @ivan
📍 команда /start

[ ✅ Принять ]  [ 🚫 Отклонить ]
```

Пока решения нет, бот ничего не хранит и не трогает чаты этого человека. После
«Принять» он получает уведомление и полный набор команд. Администратору
доступны `/users` — список и заявки, и `/revoke <id>` — закрыть доступ.

Инструкция про @BotFather показывается только администратору: включение Business
Mode — разовое действие того, кто создавал бота, остальным про это знать незачем.

## Подключение

1. [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен.
2. Там же: `/mybots` → ваш бот → **Bot Settings** → **Business Mode** →
   **Turn on**. Тумблер выключен по умолчанию, и пока он выключен Telegram
   отвечает «этот бот пока не поддерживает режим секретаря».
3. Положить токен в `BOT_TOKEN`, свой id — в `OWNER_ID`, и запустить (см. ниже).
   Без переменной берётся `FALLBACK_OWNER_ID` из `config.py` — если разворачиваете
   бота для себя, поменяйте его там или задайте переменную, иначе администратором
   останется прежний владелец.
4. Открыть чат со своим ботом → **Start**. Бот пришлёт инструкцию.
5. Настройки Telegram → **Telegram для бизнеса** → **Чат-боты** → вставить
   юзернейм бота → выбрать чаты → выдать разрешения: читать сообщения,
   отвечать, **удалять сообщения — и свои, и собеседника**.
6. Бот подтвердит подключение и покажет, какие права реально выданы.

Команда `/connect` повторяет инструкцию в любой момент, `/status` показывает
текущие права и что без них не работает.

## Три режима, которые легко перепутать

| | Про кого | Что делает | Как выключить |
|---|---|---|---|
| 🔇 **Мут** | одного человека | его новые сообщения удаляются сразу, но приходят вам | `.unmute` или кнопка в «Мутах» |
| 🌙 **Не беспокоить** | всех сразу | то же самое со всеми + вежливый автоответ от вашего имени | кнопка на своём экране, `/ungmute` |
| 🙈 **Игнор чата** | один чат | **ничего не удаляет** — бот просто перестаёт там что-либо сохранять и присылать | кнопка в «Чатах», `.ignore off` |

Коротко: мут и «не беспокоить» удаляют чужие сообщения, игнор — про то, что бот
молчит. `/chats` показывает, где вы что-то меняли, и как вернуть как было.
`/status` показывает, что сейчас включено, — если бот подозрительно тих,
смотреть надо туда.

## Что умеет

**Антиудаление.** Входящие сообщения кладутся в локальный кэш (SQLite) вместе с
`file_id` вложений. Когда сообщение удаляют, вам приходит карточка: кто, где,
когда, текст и само вложение — фото, голосовое, кружок, файл. Правки приходят
как «было → стало».

**Режим «не беспокоить».** `.gmute` в переписке или `/gmute` в чате с ботом —
и сообщения **от всех** удаляются сразу после отправки, а отправитель получает
от вашего имени:

> 🌙 Включён режим «Не беспокоить» — сообщения сейчас не доходят.
> Напишите, пожалуйста, позже.

**Срочный вызов.** Режим удаляет всё подряд, и у человека не остаётся способа
сказать, что дело не терпит. Поэтому в автоответе есть команда: собеседник
отправляет `/срочно` и пару слов о деле — вы получаете отдельное уведомление,
а он подтверждение. Один вызов в сутки от каждого человека, квота хранится в
базе и переживает перезапуск. История — `/urgent`.

Отказ на повторную попытку тоже ограничен по частоте: иначе настойчивый
собеседник устроил бы исходящий флуд вашими руками.

Слова-триггеры и срок настраиваются (`URGENT_WORDS`, `URGENT_COOLDOWN_HOURS`),
всё вместе выключается через `URGENT_ENABLED=0`. Обычная речь под это не
попадает: нужен `/` или `!` в начале сообщения, поэтому «это срочно» вызовом
не считается.

Срока у режима нет: включается и выключается вручную, `.ungmute`. Одному
человеку отвечаем не чаще раза в час, чтобы не выглядело автоответчиком. Текст
меняется переменной `DND_TEXT`. Исключения — белый список: `.allow` реплаем или
`/allow <id>`. После выключения приходит сводка: кто писал, пока вас не
беспокоили.

**Перехваченное не спамит.** Всё, что удалили мут и «не беспокоить», копится в
журнале, а не сыплется по одному сообщению в личку с ботом — иначе замученный
собеседник просто переезжает туда. Читать: `.muted`, `/intercepted`, а при
снятии мута приходит сводка «пока он был замучен, написал N сообщений» —
списком или файлом, если сообщений много. Мгновенные уведомления включаются
флагом `MUTE_LOG=1`.

Сводка **разложена по чатам**: у каждого свой заголовок с `chat_id`, числом
сообщений, вложений и периодом, а сами сообщения идут подряд внутри чата.
Сплошной лентой по времени это нечитаемо уже на втором собеседнике: глазами
нужен ответ на вопрос «что мне писал вот этот». Чат со свежим сообщением идёт
первым. Имя отправителя и причина удаления подписываются только там, где они в
чате разные, — в личке одно и то же слово у каждой строки только мешает.

Хранится перехваченное `DELETED_TTL_DAYS` дней (по умолчанию 30), считая от
момента перехвата. Чистка идёт сама, вместе с очередным бэкапом — то есть раз в
`BACKUP_EVERY_MIN` минут; она же подчищает журнал удалённых, правок и срочных
вызовов. Чтение (`.muted`, `/intercepted`, сводка при снятии мута) ничего не
удаляет: журнал можно перечитывать сколько угодно.

Раньше срока — `/clearlog`. Команда ничего не удаляет сразу: сначала показывает,
сколько сейчас хранится и сколько попадёт под чистку, и ждёт нажатия кнопки.
Варианты: всё, старше 7 или 30 дней (`/clearlog 14` — любой срок), один чат
(`/clearlog chat <id>`) или `.clearlog` прямо в переписке — тогда чистится она.
Объём чистки лежит в самой кнопке, так что передеплой между вопросом и ответом
ничего не путает, а чужое нажатие отклоняется. После чистки бот сразу обновляет
копию базы — иначе удалённое вернулось бы при восстановлении.

**Очистка переписки.** Если собеседник удаляет чат целиком, поштучные карточки
превратились бы в сотню уведомлений и упёрлись бы во флуд-лимит. Вместо этого
удаления копятся несколько секунд, складываются в одну сводку — сколько удалено,
что удалось поднять из кэша, за какой период — и к ней прикладывается вся
переписка одним текстовым файлом. Вложения досылаются следом, до
`PURGE_MEDIA_LIMIT` штук. Порог переключения — `PURGE_THRESHOLD`.

**`.mute`.** Пишете `.mute` в личке — команда исчезает из переписки, а на её
месте появляется уведомление с анимацией набора: «Вы были замучены на
неопределённый срок». Дальше все сообщения собеседника удаляются у всех сразу
после отправки, но не пропадают для вас: перехваченное приходит вам в личку с
ботом. Снимается `.unmute`.

**Досье.** `.dox` реплаем, по id или просто в личке — и бот присылает вам всё,
что о человеке накопил: имя и @username, Premium, язык, био и день рождения
(их отдаёт сам Telegram), сколько его сообщений сохранено и с какого числа,
сколько он удалял у всех и когда в последний раз, сколько правил, сколько у
него перехвачено мутом и «не беспокоить», дёргал ли срочным вызовом, в муте он
сейчас или в белом списке.

Наружу бот при этом не ходит и ничего не ищет: в карточке только его
собственная база — ваша же переписка — и то, что Telegram сам приложил к
сообщению. Поэтому и ответ уходит в личку с ботом, а не в переписку: собеседник
не видит ни команды, ни карточки.

**Необязательное.** Пачка команд, которые ничего не хранят и ни на что не
влияют, — они просто делают переписку живее. `.rose` кладёт в чат розу, `.e 🦊`
— любой эмодзи; и то и другое уходит **стикером**, а не картинкой: фото Telegram
сплющивает на белый фон, стикер остаётся прозрачным. Рисуются они на сервере из
шрифта цветных эмодзи, поэтому не зависят от чужих наборов, а `file_id` первой
отправки запоминается — дальше стикер уходит мгновенно, без перерисовки.

`.dice`, `.dart`, `.basket` и остальные кубики бросает сам Telegram, с честным
результатом и его анимацией. `.type`, `.countdown`, `.love` — анимация правкой
одного сообщения. `.roll 2d6`, `.flip`, `.8ball`, `.choose` — случайность.

**Про ритм анимации.** Пауза между кадрами считается так, чтобы кадр у
собеседника менялся ровно раз в `ANIM_DELAY`: из паузы вычитается время, которое
занимает сама правка. Иначе шаг равен `ANIM_DELAY` + скорость связи — величина,
которая гуляет от кадра к кадру, отчего анимация и дёргается. Если связь
медленнее заказанного темпа, темп подстраивается под неё: гнать кадры быстрее,
чем их доставляет Telegram, — значит копить правки в очереди и получить их
пачкой.

Стикеры бот загружает заранее, при старте: отрисовка сложного эмодзи занимает
секунды, и ждать их в момент команды незачем. Прогрев идёт беззвучно в чат
владельца и сразу подчищает за собой, а полученные `file_id` лежат в базе и
переживают передеплой вместе с ней.

### Команды в переписке (режим Business)

Пишете вы, от своего имени. 💬 — результат виден собеседнику, 🔒 — ответ
приходит только вам в чат с ботом.

| | Команда | Что делает |
|---|---|---|
| 💬 | `.mute [срок] [причина] [-all]` | удалять все новые сообщения собеседника (`-all` — во всех чатах) |
| 💬 | `.unmute` | снять мут |
| 🔒 | `.gmute` | «не беспокоить»: удалять сообщения всех подряд |
| 🔒 | `.ungmute` | выключить и получить сводку |
| 🔒 | `.allow` / `.deny` / `.allowed` | белый список для «не беспокоить» |
| 🔒 | `.muted [N]` | что перехвачено мутом и «не беспокоить» |
| 🔒 | `.mutelist` | список активных мутов |
| 🔒 | `.del` (реплаем) | удалить сообщение у всех |
| 🔒 | `.purge` (реплаем) | удалить всё от реплая до текущего |
| 🔒 | `.clearlog` | почистить журнал перехваченного этого чата |
| 🔒 | `.deleted [N]` | последние удалённые в этом чате |
| 🔒 | `.chats` | где вы меняли настройки и как вернуть |
| 🔒 | `.urgent` | срочные вызовы от собеседников |
| 🔒 | `.id` | id чата и собеседника |
| 🔒 | `.dox [reply\|id]` | досье: всё, что бот записал про человека |
| 🔒 | `.export` | весь журнал удалённых этого чата файлом |
| 🔒 | `.antidelete on/off`, `.ignore` | настройки для этого чата |
| 🔒 | `.id`, `.ping`, `.stats`, `.help` | диагностика |

Сроки: `10m`, `2h`, `1d`, `1w` (без единицы — минуты). Флаг `-q` отключает
анимацию.

Развлечения — всё 💬, видно собеседнику:

| Команда | Что делает |
|---|---|
| `.rose` `.heart` `.fire` `.cat` `.party` `.kiss` `.cry` `.think` `.ok` `.clown` | эмодзи стикером, без фона |
| `.e <эмодзи>` | то же самое с любым эмодзи |
| `.dice` `.dart` `.basket` `.foot` `.bowl` `.slot` | кубики Telegram с его анимацией |
| `.type <текст>` | печатает текст по словам, с курсором |
| `.countdown [N]` | обратный отсчёт и «поехали» |
| `.love` | растущее сердце |
| `.flip` · `.roll [2d6]` | монетка и кубики |
| `.8ball <вопрос>` · `.choose а \| б` | шар предсказаний и выбор |

### Команды в чате с ботом

`/gmute` · `/ungmute` · `/allow` · `/deny` · `/allowed` · `/urgent` ·
`/intercepted [N]` · `/clearlog` · `/deleted [N]` · `/dox <id>` · `/chats` ·
`/find <текст>` · `/mutes` · `/unmute <id>` · `/export` · `/status` ·
`/connect` · `/help`

Только администратору: `/users` · `/revoke <id>` · `/backup`

`/find` ищет по всему сохранённому — и по удалённым, и по перехваченным.
`/export` отдаёт весь журнал одним файлом.

### Дополнительно в режиме юзербота

Те же команды плюс группы: `.ban` `.kick` `.tmute` `.promote` `.pin`,
`.purgeme`, `.sd`, `.afk`, заметки `.save`/`.get`/`.notes`, `.restore`,
`.export`, `.restart`, `.update`. Полный список — `.help`.

## Запуск

```bash
git clone <репозиторий> && cd new2
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # достаточно заполнить BOT_TOKEN
python main.py
```

Через Docker:

```bash
docker compose up -d --build
docker compose logs -f
```

Режим юзербота (необязательно): взять `API_ID` / `API_HASH` на
`my.telegram.org`, затем `python scripts/gen_session.py` и вписать `SESSION`.
Строка сессии = полный доступ к аккаунту, в git ей не место.

## Хостинг

Из бесплатных без привязки карты сейчас работает **Render**: подключаете
репозиторий, задаёте `BOT_TOKEN` — и всё. Публичный адрес Render передаёт сам,
бот видит его и включает вебхук вместо постоянного опроса. Пошагово и с
альтернативами (Hugging Face Spaces, Fly.io, своя машина) — в
[DEPLOY.md](DEPLOY.md).

Всё, что вы настраиваете — муты, белый список, игнор чатов, выданный доступ, —
лежит в базе, а не в памяти; в памяти только читаемая копия, которую бот
поднимает из базы при старте.

Проблема в другом: файл базы на бесплатных тарифах живёт на временном диске и
пропадает при каждом обновлении. Поэтому бот присылает себе копию базы в вашу
личку и **закрепляет** её (`BACKUP_EVERY_MIN`), а после каждой правки настроек
делает это отдельно, не дожидаясь расписания (`BACKUP_SOON_SEC`) — иначе
обновление через пять минут после настройки стирало бы её. Историю чата
бот прочитать не может, а закреплённое сообщение — может, и при старте
поднимает базу оттуда сам. Для этого нужен только `OWNER_ID`: без него бот не
знает, в какую личку смотреть. Резервный путь на все случаи — переслать боту
файл бэкапа вручную, он проверит целостность и подставит его.

Подключение к чатам восстанавливается отдельно и без всяких условий: Telegram
присылает `business_connection` только когда подключение меняется, поэтому бот
перечитывает связку по первому же событию из личных чатов. Переподключать
в настройках ничего не нужно — достаточно написать что угодно в любой личке.
Пока владелец неизвестен, бот принципиально ничего не удаляет: иначе не
отличить ваши сообщения от чужих.

На хостах с постоянным томом (Fly.io) всё это не нужно.

## Настройки

Все параметры с комментариями — в [`.env.example`](.env.example).

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BOT_TOKEN` | — | токен из @BotFather (режим Business) |
| `OWNER_ID` | из `config.py` | id администратора: выдаёт доступ, владеет базой |
| `SESSION` | — | строка сессии (режим юзербота) |
| `PREFIX` | `.` | префикс команд в переписке |
| `MUTE_ANIM` | `type` | `type` / `bar` / `off` — стиль анимации |
| `ANIM_DELAY` | `0.6` | сколько держится кадр анимации, сек |
| `ANTIDELETE_GROUPS` | `0` | антиудаление в группах (только юзербот) |
| `CACHE_TTL_HOURS` | `720` | сколько держать сообщения в памяти (30 дней) |
| `DELETED_TTL_DAYS` | `30` | сколько держать журнал удалённых и перехваченных |
| `BACKUP_EVERY_MIN` | `60` | период копии базы |
| `BACKUP_SOON_SEC` | `60` | через сколько сохранять копию после правки настроек |
| `PURGE_THRESHOLD` | `5` | с какого числа удалений слать сводку файлом |
| `WEBHOOK_URL` | — | публичный адрес; задан — работает вебхук, иначе опрос |

Антиудаление по умолчанию работает **только в личках**. В группах его нужно
включать точечно (`.antidelete on`) — чтобы не собирать переписку посторонних.

## Разработка

```bash
pip install -r requirements-dev.txt
pytest -q        # 452 теста
ruff check .
```

Структура:

```
bot/        Bot API: клиент, polling, режим Business, команды «.» и «/»
core/       общий движок: анимация, диспетчер юзербота, отчёты, бэкапы
modules/    команды и обработчики юзербота, по файлу на раздел
db.py       SQLite: кэш, журнал удалений, муты, настройки, подключения
web.py      HTTP: healthcheck и приём вебхука
main.py     запуск режимов и выбор транспорта
```

Новая команда в переписке — функция с `@bizcmd(...)` в `bot/dotcmd.py`,
новая команда юзербота — `@command(...)` в любом модуле `modules/`.
