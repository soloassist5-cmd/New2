# Деплой на бесплатный хостинг

Боту нужен процесс, который живёт постоянно и слушает `$PORT`. Практически все
оставшиеся бесплатные тарифы — это **web service**, поэтому по умолчанию бот
работает через **вебхук**: Telegram сам присылает апдейты на публичный адрес
сервиса, постоянный опрос не нужен. Если публичного адреса нет (своя машина,
Docker дома), бот автоматически переключается на long polling.

> Бесплатные тарифы регулярно закрываются. Koyeb, который раньше был лучшим
> вариантом, в 2026-м вошёл в Mistral и больше не принимает новые сервисы —
> дашборд у существующих аккаунтов пустой. Поэтому ниже несколько площадок:
> проект собирается в обычный Docker-образ и переезжает между ними без правок.

## Шаг 0. Подготовка — две минуты

1. [@BotFather](https://t.me/BotFather) → `/newbot` → имя и юзернейм → токен
   вида `8123456789:AAH...`. Это `BOT_TOKEN`, единственный обязательный секрет.
2. Там же включить режим Business: `/mybots` → ваш бот → **Bot Settings** →
   **Business Mode** → **Turn on**. По умолчанию выключен, и без него Telegram
   не даст подключить бота: «этот бот пока не поддерживает режим секретаря».
3. Запушить репозиторий на GitHub.

Нужен **Telegram Premium** — раздела «Telegram для бизнеса» без подписки нет.
Если Premium нет, разверните режим юзербота: `API_ID` и `API_HASH` с
`my.telegram.org`, локально `python scripts/gen_session.py`, полученный
`SESSION` — в секреты.

## Сравнение площадок

| Платформа | Деплой из GitHub | Засыпает | Карта | Диск |
|---|---|---|---|---|
| **Render** (free web) | да, автодеплой на push | через ~15 мин простоя | нет | эфемерный |
| **Hugging Face Spaces** | через git push / Action | после долгого простоя | нет | эфемерный |
| **Fly.io** | через GitHub Actions | нет | да | **постоянный том** |
| **Oracle Cloud Always Free** | по SSH | нет | да | свой |
| Своя машина / старый телефон | — | нет | нет | свой |
| Railway, Heroku | да | — | — | бесплатных тарифов нет |
| GitHub Actions как хост | — | лимит 6 ч на job | — | нарушает правила |
| Vercel, Netlify | да | serverless | нет | долгоживущего процесса нет |

Коротко: **без карты — Render**, **надёжнее всего — Fly.io или Oracle**,
**бесплатнее и стабильнее всего — старый телефон дома**.

## Вариант A. Render — без карты, деплой из GitHub

1. Дашборд → *Blueprints* → *New Blueprint Instance* → выбрать репозиторий.
   Render подхватит [`render.yaml`](render.yaml) и создаст web-сервис из
   Dockerfile.
2. Заполнить секрет `BOT_TOKEN` (в файле он `sync: false`, то есть задаётся
   только в UI и в git не попадает).
3. Всё. `WEBHOOK_URL` указывать не нужно: Render сам передаёт
   `RENDER_EXTERNAL_URL`, бот это видит и включает вебхук.

**Про засыпание.** Бесплатный web-сервис останавливается после ~15 минут без
входящих запросов, а холодный старт занимает около минуты. Вебхук это частично
лечит сам — Telegram повторяет доставку, — но сообщение может прийти с
задержкой, а `.mute` должен срабатывать мгновенно. Поэтому заведите бесплатный
HTTP-монитор на [UptimeRobot](https://uptimerobot.com) или cron-job.org:
адрес `https://<service>.onrender.com/health`, интервал 5 минут. Он и держит
сервис бодрым.

Бесплатных инстанс-часов хватает ровно на один сервис в режиме 24/7 — второй
уже не поместится. Условия тарифа меняются, сверьтесь с актуальными.

Автодеплой на push в `main` включён (`autoDeploy: true`).

## Вариант B. Hugging Face Spaces — тоже без карты

Docker-Spaces на бесплатном CPU крутятся круглосуточно.

1. huggingface.co → *New Space* → SDK **Docker**, видимость **Private**.
2. Запушить туда содержимое репозитория (Space — это обычный git-репозиторий).
3. *Settings* → *Variables and secrets* → секрет `BOT_TOKEN`, переменная
   `WEBHOOK_URL=https://<user>-<space>.hf.space`, `PORT=7860`.
4. В `Dockerfile` поменять `EXPOSE 8080` на `7860` либо задать `PORT=7860`
   переменной — Spaces ждут именно этот порт.

Space засыпает после длительного простоя — держите тем же пингом на `/health`.
Диск эфемерный, база — как в разделе про эксплуатацию ниже.

## Вариант C. Fly.io — единственный с постоянным диском

База переживает передеплой без ручных действий.

```bash
fly launch --no-deploy            # подхватит fly.toml
fly volumes create guard_data --size 1 --region fra
fly secrets set BOT_TOKEN=... WEBHOOK_URL=https://<app>.fly.dev
fly deploy
```

Для деплоя из GitHub: `fly tokens create deploy`, положить в секрет
`FLY_API_TOKEN`, запускать [`deploy-fly.yml`](.github/workflows/deploy-fly.yml).
Ключевое в `fly.toml` — `auto_stop_machines = false`, иначе машина остановится.
Нужна привязка карты, списаний в пределах бесплатных лимитов нет.

---

## Вариант D. Своя машина

Oracle Cloud Always Free (ARM-инстанс, бессрочно), Raspberry Pi или старый
Android с Termux. Публичного адреса обычно нет — бот сам выберет long polling.

```bash
git clone <репозиторий> && cd new2
cp .env.example .env && nano .env        # достаточно BOT_TOKEN
docker compose up -d --build
```

`restart: unless-stopped` поднимет контейнер после перезагрузки. На Android:
`pkg install python git`, `termux-wake-lock`, автозапуск через Termux:Boot.

## После деплоя

1. `https://<адрес>/health` → должно быть `{"status":"ok","bot":true,
   "transport":"webhook"}`.
2. Открыть чат со своим ботом, нажать **Start** — придёт инструкция.
3. Настройки Telegram → **Telegram для бизнеса** → **Чат-боты** → вставить
   юзернейм бота → выдать права, включая удаление сообщений. Если Telegram
   пишет «не поддерживает режим секретаря» — не включён Business Mode в
   @BotFather, см. шаг 0.
4. Бот подтвердит подключение и покажет, какие права реально выданы.
5. Проверка: `.ping` в любом личном чате.

## Эксплуатация

**Живость.** `/health` отдаёт `bot`, `transport`, `business_connections`,
`userbot`, аптайм и число мутов. В Telegram — `/status`.

**Данные на эфемерном диске.** Раз в `BACKUP_EVERY_MIN` минут бот присылает
себе копию базы файлом. После передеплоя перешлите этот файл боту — он
проверит целостность и подставит вместо текущей базы; чужой или битый файл
отклонит, ничего не тронув. Вручную копия — `/backup`.

**После передеплоя бот «забыл» подключение.** Связка хранится в базе, а диск на
бесплатных тарифах эфемерный. Лечится само, но по-разному:

* **Подключение** — напишите что-нибудь в любом личном чате. Бот перечитает его
  у Telegram и пришлёт «Подключение восстановлено». Переподключать в настройках
  не нужно. Команда `/start` сразу после передеплоя связку ещё не видит — это
  нормально, ей неоткуда взяться до первого события.
* **База целиком** (журнал, муты, белый список) — задайте `OWNER_ID` в
  переменных окружения. Бот присылает копию базы вам в личку и закрепляет её, а
  при старте забирает закреплённое сообщение и поднимает базу сам. Свой id
  подскажет `/start` или команда `.id` в любом личном чате.

Без `OWNER_ID` база после передеплоя теряется — останется только переслать боту
последний файл бэкапа вручную.

**Отчёты не приходят.**
1. `/health` → `bot: true`? Нет — неверный `BOT_TOKEN`.
2. `business_connections: 0` → бот не подключён к чатам, см. `/connect`.
3. `/status` покажет выданные права. Нет «удалять сообщения собеседника» — не
   работает `.mute`; нет «читать сообщения» — не работает ничего.
4. `bot_reachable: false` → бот не может писать вам первым, нажмите Start.

**Вебхук не доходит.** Telegram требует HTTPS на публичном адресе. Проверить
состояние можно так:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

В ответе интересны `url`, `pending_update_count` и `last_error_message`. Если
сервис за это время переехал, достаточно передеплоить — адрес выставляется
заново при каждом старте. Убрать вебхук и вернуться к опросу — очистить
`WEBHOOK_URL`.

**Два экземпляра сразу.** Bot API не разрешает двум процессам читать апдейты
одного бота: в логах появится `409`. Убедитесь, что старый деплой остановлен.
